## 1. Authentication

**Base**: `/api/auth`

| Method | Endpoint | Permission | Description |
|--------|----------|------------|-------------|
| POST | `/login/step1` | 🔓 Public | Login step 1 - validate username/password |
| POST | `/login/step2` | 🔓 Public | Login step 2 - validate TOTP code |
| POST | `/setup-2fa` | 🔐 Temp Token | Setup 2FA for first-time users |
| POST | `/verify-2fa` | 🔐 Temp Token | Verify 2FA setup |
| POST | `/logout` | 🔐 Authenticated | Logout (invalidate trusted device) |

### Login Flow

```
Step 1: POST /auth/login/step1
  Request: { username, password, device_fingerprint?, device_name? }
  Response: { temp_token?, access_token?, totp_required, message }

Step 2: POST /auth/login/step2 (if totp_required)
  Request: { temp_token, totp_code, remember_device?, device_fingerprint? }
  Response: { access_token, user_id, username, role }
```

## 2. Users

**Base**: `/api/users`

| Method | Endpoint | Permission | Description |
|--------|----------|------------|-------------|
| GET | `/` | 🔐 Authenticated | List all users (paginated) |
| GET | `/{user_id}` | 🔐 Authenticated | Get user by ID |
| POST | `/` | 🔑 Admin | Create new user |
| PUT | `/{user_id}` | 🔐 Self or Admin | Update user information |
| DELETE | `/{user_id}` | 🔑 Admin | **Hard delete** user permanently |
| POST | `/{user_id}/reset-2fa` | 🔑 Admin | Reset user's 2FA |
| PUT | `/{user_id}/password` | 🔐 Self or Admin | Change user password |

### Notes
- Users cannot delete themselves
- Non-admin users can only see active users
- Hard delete permanently removes user from database

## Common Request/Response Patterns

### Pagination

All list endpoints support pagination:
```
GET /api/equipment?skip=0&limit=100
```

### Error Responses

```json
{
  "detail": "Error message here"
}
```

Common HTTP Status Codes:
- `200` - Success
- `201` - Created
- `204` - No Content (successful delete)
- `400` - Bad Request
- `401` - Unauthorized (not authenticated)
- `403` - Forbidden (insufficient permissions)
- `404` - Not Found
- `422` - Validation Error
- `500` - Internal Server Error

### Authentication Header

All authenticated endpoints require:
```
Authorization: Bearer {access_token}
```

## Asset Code Format

### Equipment
```
{CATEGORY}-{YEAR}-{SEQUENCE}
Example: MBES-2024-001, GNSS-2023-015
```

### Sub-Equipment
```
{PARENT_ASSET_CODE}-{SUB_SEQUENCE}
Example: MBES-2024-001-01, MBES-2024-001-02
```

- Sequence: 3 digits for equipment (001-999)
- Sub-sequence: 2 digits for sub-equipment (01-99)
- Auto-generated and unique per category/year

---

## QR Code URL Format

```
{protocol}://{domain}/e/{asset_code}
Example: http://localhost:5173/e/MBES-2024-001
```

Configured via environment variables:
- `QR_CODE_DOMAIN` (default: localhost:5173)
- `QR_CODE_PROTOCOL` (default: http)

## Activity Log Editing (NEW in v1.1)

**Endpoint**: `PUT /api/equipment/{equipment_id}/logs/{log_id}`
**Permission**: 👔 Manager+

### Editable Fields
- `description` - Log description text
- `latitude` - GPS latitude coordinate
- `longitude` - GPS longitude coordinate

### Non-Editable Fields (Read-only)
- `log_type` - Type of log entry
- `old_value` - Previous value
- `new_value` - New value
- `created_at` - Creation timestamp
- `created_by` - Creator user ID

### Edit Tracking
All edits are tracked with:
- `edited_at` - Last edit timestamp
- `edited_by` - User who edited
- `edit_count` - Number of edits
- `original_description` - Original description (saved on first edit)
- `original_latitude` - Original latitude (saved on first edit)
- `original_longitude` - Original longitude (saved on first edit)

## Sub-Equipment Management (NEW in v1.1)

### Use Case
Track components of main equipment (e.g., POSMV320 includes 2 antennas, 2 cables, IMU cable, IMU main unit)

### Features
- Independent asset code and QR code
- Independent status tracking
- Independent maintenance logs
- Can be viewed/managed separately from parent equipment

### Relationship
- Each sub-equipment belongs to one parent equipment
- Cascade delete: deleting parent equipment soft-deletes all sub-equipment
- Sub-equipment logs marked with `is_sub_equipment=True`

- `users` - User accounts
- `equipments` - Main equipment
- `sub_equipments` - Sub-equipment/components (NEW)
- `equipment_logs` - Activity logs (with edit tracking)

- `customers` - Customer companies
- `rentals` - Rental records
- `calibrations` - Calibration records
- `log_attachments` - Log file attachments
- `trusted_devices` - 2FA trusted devices

### Relationships
- Equipment → Sub-Equipment (1:N, cascade delete)
- Equipment → Logs (1:N, cascade delete)
- Equipment → Location (N:1)
- Log → Attachments (1:N, cascade delete)
- Rental → Equipment (N:1)
- Rental → Customer (N:1)
- Calibration → Equipment (N:1)

## Security Notes

### Authentication
- Two-factor authentication (TOTP) required
- Trusted device support (7-day remember)
- JWT token-based authentication
- Device fingerprinting for trusted devices

### Permissions
- Role-based access control (RBAC)
- Endpoint-level permission checks
- Cannot delete own user account
- Cannot modify logs created by others (except description/GPS with Manager+)

### Data Protection
- Soft delete for equipment (preserves history)
- Hard delete for users and calibrations (permanent removal)
- All equipment changes logged
- Edit history tracked for log modifications
