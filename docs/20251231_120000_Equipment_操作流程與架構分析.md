## 1. 路由架構

### Equipment 主要路由

| 路徑 | Name | 組件 | 權限要求 | 說明 |
|------|------|------|----------|------|
| `/equipment` | equipment-list | EquipmentListView | 已登入 | 設備列表頁（含篩選） |
| `/equipment/new` | equipment-create | EquipmentFormView | Manager+ | 新增設備表單 |
| `/equipment/:id` | equipment-detail | EquipmentDetailView | 已登入 | 設備詳細資訊 |
| `/equipment/:id/edit` | equipment-edit | EquipmentFormView | Manager+ | 編輯設備表單 |
| `/e/:assetCode` | equipment-scan | EquipmentScanView | 公開 | QR Code 掃描入口 |

### Sub-Equipment 路由

| 路徑 | Name | 組件 | 權限要求 | 說明 |
|------|------|------|----------|------|
| `/sub-equipment/:id` | sub-equipment-detail | SubEquipmentDetailView | 已登入 | 子設備詳細資訊 |

### 路由特性

- **公開路由**: `/e/:assetCode` 可在未登入狀態存取，僅顯示基本資訊
- **保護路由**: 其他路由皆需登入，由 `router.beforeEach` 守衛控制
- **權限檢查**: `requiresManager` meta 用於管理員操作
- **重複使用**: EquipmentFormView 同時處理新增和編輯（透過 `isEdit` computed）

## 2. 頁面組件功能

### 2.1 EquipmentListView.vue

**主要功能**:
- 顯示所有設備的卡片式列表（Desktop: 3 欄 Grid, Mobile: 單欄）
- 多重篩選條件（Search, Category, Status）
- 即時搜尋（500ms debounce）
- 分頁顯示（預設 50 筆）

**操作流程**:
```
進入頁面 → 自動載入設備列表 → 使用者可：
├─ 輸入搜尋關鍵字（500ms 後觸發 API）
├─ 選擇分類篩選（立即觸發 API）
├─ 選擇狀態篩選（立即觸發 API）
├─ 點擊 Reset 清除所有篩選
├─ 點擊設備卡片 → 導向詳細頁面
└─ (Manager+) 點擊 "Add Equipment" → 導向新增頁面
```

**UI 特色**:
- 狀態徽章（Status Badge）顏色區分：
  - Ordering: 黃色
  - In Stock: 綠色
  - Deployed: 藍色
  - Rented: 紫色
  - Repair: 橘色
  - Calibrating: 青色
  - Disposed: 灰色
  - Lost: 紅色

**資料來源**:
- Store: `equipmentStore.equipmentList`, `equipmentStore.total`
- API: `equipmentApi.list(filters)`

### 2.2 EquipmentDetailView.vue

**主要功能**:
- 顯示設備完整詳細資訊
- QR Code 顯示與下載
- 狀態操作按鈕（Deploy, Return, Repair, Calibration）
- Activity Log 查看與編輯（Manager+）
- Sub-Equipment 子設備管理
- 附件上傳與管理

**頁面區塊**:

1. **Header 區域**
   - Asset Code 標題
   - Manufacturer & Model
   - 操作按鈕：Edit (Manager+), Download QR, Delete (Admin)

2. **Status Badge**
   - 當前狀態大型徽章

3. **Basic Information 卡片**
   - Asset Code, Category, Manufacturer, Model, Serial Number

4. **Equipment Photo 卡片**
   - 設備照片顯示（若有上傳）

5. **Documents & Reports 卡片**
   - Purchase Date
   - Equipment Manual 下載連結
   - Calibration Report 下載連結

6. **QR Code 卡片**
   - QR Code 圖片顯示（Base64）
   - QR Code URL 文字

7. **Specifications 卡片**
   - 技術規格文字區域

8. **Status Actions 區域** (Operator+ 且狀態可操作時)
   - Deploy Equipment (狀態為 in_stock 或 ordering)
   - Return Equipment (狀態為 deployed 或 rented)
   - Send to Repair (狀態為 in_stock 或 deployed)
   - Send to Calibration (狀態為 in_stock 或 deployed)

9. **Sub-Equipment Section**
   - 嵌入 `SubEquipmentList` 組件
   - 顯示所有子設備

10. **Activity Log 表格**
    - 顯示所有活動記錄
    - Manager+ 可編輯 Description 和 GPS
    - 顯示編輯歷史（edited ×N）
    - 附件管理（View, Upload, Delete）

**操作流程**:
```
進入頁面 → 載入設備、QR Code、Logs → 使用者可：
├─ (Manager+) 點擊 Edit → 導向編輯頁面
├─ 點擊 Download QR → 開啟 QR Code 圖片下載
├─ (Admin) 點擊 Delete → 軟刪除設備（is_active=false）
├─ (Operator+) 執行狀態操作：
│  ├─ Deploy → 顯示 Deploy Modal（選擇 Location）
│  ├─ Return → 顯示 Return Modal（選擇 Location）
│  ├─ Send to Repair → prompt 輸入 notes
│  └─ Send to Calibration → prompt 輸入 notes
├─ (Manager+) 點擊 Log 的 Edit → 開啟 Edit Log Modal
│  └─ 修改 Description, Latitude, Longitude
├─ 點擊 Log 的 View Attachments → 開啟 Attachments Modal
│  ├─ 查看現有附件
│  ├─ 下載附件
│  ├─ 刪除附件
│  └─ 上傳新附件
└─ 查看 Sub-Equipment 列表
   ├─ (Manager+) Add Component
   ├─ 點擊 View → 導向子設備詳細頁面
   ├─ (Manager+) Edit 子設備
   └─ (Manager+) Delete 子設備
```

**資料來源**:
- Store: `equipmentStore.currentEquipment`
- API:
  - `equipmentApi.get(id)` - 設備資訊
  - `equipmentApi.getQRCode(id)` - QR Code Base64
  - `equipmentApi.getLogs(id)` - Activity Logs
  - `equipmentApi.updateLog(equipmentId, logId, data)` - 編輯 Log
  - `/api/equipment-logs/${logId}/attachments` - 附件 CRUD

### 2.3 EquipmentFormView.vue

**主要功能**:
- 新增/編輯設備（同一組件，透過 `isEdit` 區分）
- 表單驗證
- 檔案上傳（僅編輯模式）
- 維護記錄管理（僅編輯模式）

**表單欄位**:

**基本資訊** (新增 & 編輯)
- Category* (下拉選單)
- Manufacturer* (文字輸入)
- Model* (文字輸入)
- Serial Number (文字輸入)

**狀態** (僅編輯模式)
- Equipment Status (下拉選單)

**日期**
- Purchase Date (日期選擇器)

**檔案上傳** (僅編輯模式)
- Equipment Photo (圖片上傳)
- Equipment Manual (PDF/DOC 上傳)
- Calibration Report (PDF 上傳)
- 使用 `FileUpload` 組件，支援上傳、查看、刪除

**維護記錄** (僅編輯模式)
- Last Maintenance Date (日期選擇器)
- Next Maintenance Due (日期選擇器)
- Maintenance Notes (文字區域)

**其他**
- Specifications (文字區域)
- General Notes (文字區域)

**操作流程**:

**新增設備**:
```
進入新增頁面 → 填寫表單 → 驗證（Category, Manufacturer, Model 必填）→ 提交：
├─ 成功：顯示成功訊息（含 Asset Code）→ 1 秒後導向詳細頁面
└─ 失敗：顯示錯誤訊息
```

**編輯設備**:
```
進入編輯頁面 → 載入現有資料 → 修改表單 → 可上傳/刪除檔案 → 提交：
├─ 成功：導向詳細頁面
└─ 失敗：顯示錯誤訊息
```

**檔案上傳流程** (透過 FileUpload 組件):
```
選擇檔案 → Upload → API 上傳成功 → 更新 URL → 重新載入設備資料
刪除檔案 → 確認 → API 刪除成功 → 清除 URL → 重新載入設備資料
```

**資料來源**:
- Store: `equipmentStore.currentEquipment` (編輯模式)
- API:
  - `equipmentApi.create(data)` - 新增
  - `equipmentApi.update(id, data)` - 更新
  - `/api/uploads/equipment/{id}/...` - 檔案上傳

### 2.4 EquipmentScanView.vue

**主要功能**:
- QR Code 掃描入口（公開路由）
- 未登入：顯示基本資訊 + 登入提示
- 已登入：顯示完整資訊 + 記錄掃描事件（含 GPS）

**頁面邏輯**:

**未登入狀態**:
```
掃描 QR Code (/e/MBES-2024-001) →
├─ 顯示：Asset Code, Manufacturer, Model, Category, Serial Number, Status
└─ 顯示登入提示："Login to View Full Details" 按鈕
```

**已登入狀態**:
```
掃描 QR Code →
├─ 自動記錄掃描事件（addNote API）
├─ 嘗試取得 GPS 定位：
│  ├─ 成功：記錄 "QR code scanned via mobile" + GPS 座標
│  ├─ 失敗/拒絕：記錄 "QR code scanned via mobile (no GPS)"
│  └─ 不支援：記錄 "QR code scanned via mobile (no GPS support)"
├─ 顯示成功訊息："Scan recorded with location data"
└─ 提供操作：
   ├─ View Full Details → 導向 EquipmentDetailView
```

**資料來源**:
- API: `equipmentApi.getByQR(assetCode)`
- GPS: `navigator.geolocation.getCurrentPosition()`

## 3. 權限控制

### 角色定義

系統採用階層式權限：**Admin > Manager > Operator > Viewer**

| 角色 | 說明 |
|------|------|
| **Viewer** | 僅查看權限，無法進行任何操作 |
| **Operator** | 可執行設備狀態變更操作（Deploy, Return, Repair） |
| **Manager** | 可新增/編輯設備、編輯 Log、管理子設備 |
| **Admin** | 完整權限，包含刪除設備 |

### Equipment 各功能權限需求

| 功能 | 最低權限 | 檢查點 | 說明 |
|------|----------|--------|------|
| 查看設備列表 | 已登入 | Router Guard | 所有登入用戶可查看 |
| 查看設備詳情 | 已登入 | Router Guard | 所有登入用戶可查看 |
| QR Code 掃描基本資訊 | 公開 | 無 | 未登入也可查看基本資訊 |
| 新增設備 | Manager+ | Router Guard, UI Button | `authStore.isManager` |
| 編輯設備 | Manager+ | Router Guard, UI Button | `authStore.isManager` |
| 刪除設備 | Admin | UI Button | `authStore.isAdmin` |
| Deploy/Return 設備 | Operator+ | UI Button | `authStore.isOperator` |
| Send to Repair/Calibration | Operator+ | UI Button | `authStore.isOperator` |
| 編輯 Activity Log | Manager+ | UI Button | `authStore.isManager` |
| 新增 Sub-Equipment | Manager+ | UI Button | `authStore.isManager` |
| 編輯 Sub-Equipment | Manager+ | UI Button | `authStore.isManager` |
| 刪除 Sub-Equipment | Manager+ | UI Button | `authStore.isManager` |
| 下載 QR Code | 已登入 | UI Button | 所有登入用戶 |

### 前端權限檢查方式

```vue
<!-- 範例 1: 新增設備按鈕 -->
<AppButton v-if="authStore.isManager" @click="...">
  Add Equipment
</AppButton>

<!-- 範例 2: 刪除按鈕 -->
<AppButton v-if="authStore.isAdmin" @click="...">
  Delete
</AppButton>

<!-- 範例 3: 狀態操作區域 -->
<div v-if="authStore.isOperator && canPerformActions">
  <!-- Deploy, Return 等按鈕 -->
</div>

<!-- 範例 4: 編輯 Log 按鈕 -->
<button v-if="authStore.isManager" @click="openEditLogModal(log)">
  Edit
</button>
```

### 後端權限驗證

後端 API 使用 dependency injection 進行權限驗證：

```python
# 範例：新增設備需要 Manager+ 權限
@router.post("", response_model=EquipmentResponse)
async def create_equipment(
    data: EquipmentCreateRequest,
    current_user: User = Depends(require_manager),  # 權限檢查
    db: AsyncSession = Depends(get_db)
):
    # ...
```

## 4. 完整操作流程

### 4.1 設備生命週期完整流程

```
[新增設備]
Manager 登入 → Equipment List → "Add Equipment" → 填寫表單 →
選擇 Category, Manufacturer, Model, Serial Number, Purchase Date →
提交 → 系統自動產生 Asset Code (e.g., MBES-2025-001) →
自動產生 QR Code → 狀態預設為 "Ordering" → 建立成功

[入庫]
進入設備詳細頁 → Manager 點擊 Edit → 修改 Status 為 "In Stock" →
(可選) 上傳設備照片、使用手冊、校正報告 → 儲存

[部署]
Operator 進入設備詳細頁 → 點擊 "Deploy Equipment" →
選擇部署地點 → 輸入備註 → (自動抓取 GPS) → 確認 →
狀態變更為 "Deployed" → 記錄 Activity Log (status_change + location_change)

[回收]
設備使用完畢 → Operator 點擊 "Return Equipment" →
選擇回收地點 → 輸入備註 → 確認 →
狀態變更為 "In Stock" → 記錄 Activity Log

[送修]
設備故障 → Operator 點擊 "Send to Repair" →
輸入維修原因 → 確認 →
狀態變更為 "Repair" → 記錄 Activity Log

[校正]
需要校正 → Operator 點擊 "Send to Calibration" →
輸入備註 → 確認 →
狀態變更為 "Calibrating" → 記錄 Activity Log →
(在 Calibration 模組建立校正記錄)

[報廢]
設備損壞無法修復 → Manager 進入編輯頁面 →
修改 Status 為 "Disposed" → 儲存 →
設備不再出現在可操作列表中

[遺失]
設備遺失 → Manager 修改 Status 為 "Lost" →
記錄遺失原因 → 儲存
```

### 4.2 Sub-Equipment 管理流程

```
[新增子設備]
進入主設備詳細頁 → Sub-Equipment Section →
Manager 點擊 "Add Component" → 填寫表單：
├─ Component Name* (e.g., "Antenna 1", "IMU Cable")
├─ Serial Number (選填)
└─ Notes (選填)
→ 提交 → 系統自動產生 Asset Code (e.g., MBES-2025-001-01) →
自動產生獨立 QR Code → 狀態預設為 "In Stock" → 建立成功

[編輯子設備]
Sub-Equipment List → Manager 點擊 "Edit" →
修改 Component Name, Serial Number, Status, Notes → 儲存

[查看子設備詳情]
點擊 "View" → 進入 SubEquipmentDetailView →
顯示：Asset Code, Component Name, Serial Number, Status,
Parent Equipment Link, QR Code, Activity Log

[刪除子設備]
Manager 點擊 "Delete" → 確認對話框 → 確認刪除 →
子設備及其 Activity Log 被刪除（CASCADE）
```

### 4.3 Activity Log 編輯流程

```
[編輯 Log]
進入設備詳細頁 → Activity Log 表格 →
Manager 點擊某一筆 Log 的 "Edit" → 開啟 Edit Log Modal →

顯示 (唯讀):
├─ Log Type (e.g., "Status Change", "Maintenance")
├─ Created At & Created By
├─ Old Value & New Value (若有)
└─ Edit History (若有編輯過)

可編輯:
├─ Description* (必填)
├─ Latitude (選填)
└─ Longitude (選填)

→ 修改內容 → 點擊 "Save Changes" →

後端處理:
├─ 第一次編輯：儲存 original_description, original_latitude, original_longitude
├─ 更新 description, latitude, longitude
├─ 記錄 edited_at, edited_by
└─ edit_count += 1

→ 更新成功 → Log 顯示 "(edited ×N)" 標記
```

### 4.4 QR Code 掃描流程

```
[場景：現場人員使用手機掃描設備 QR Code]

未登入狀態:
掃描 QR Code → 進入 /e/MBES-2024-001 →
顯示基本資訊（Asset Code, Manufacturer, Model, Status）→
顯示 "Login to View Full Details" 按鈕 →
點擊登入 → 導向登入頁面 → 登入成功後返回設備頁面

已登入狀態:
掃描 QR Code → 進入 /e/MBES-2024-001 →
自動嘗試取得 GPS 定位 →
├─ GPS 成功：記錄 "QR code scanned via mobile" + 座標
└─ GPS 失敗：記錄 "QR code scanned via mobile (no GPS)"
→ 顯示 "Scan recorded with location data" 成功訊息 →
提供選項:
├─ "View Full Details" → 進入完整設備詳細頁面
└─ "Back to Equipment List" → 返回設備列表
```

### 4.5 附件管理流程

```
[上傳附件到 Activity Log]
進入設備詳細頁 → Activity Log →
點擊某一筆 Log 的 "View" → 開啟 Attachments Modal →

Upload New Attachment:
├─ 選擇附件類型（Calibration Report, Damage Photo, Repair Document 等）
├─ 輸入 Description (選填)
├─ 選擇檔案
└─ 點擊 "Upload" → 上傳成功 → 顯示在附件列表

[查看/下載附件]
點擊附件檔名 → 在新分頁開啟/下載檔案

[刪除附件]
點擊 "Delete" → 確認對話框 → 確認刪除 → 附件被移除
```

## 5. 資料流與狀態管理

### 5.1 Pinia Store 架構

**equipmentStore** (`stores/equipment.ts`)

**State**:
```typescript
{
  equipmentList: Equipment[]      // 設備列表
  currentEquipment: Equipment | null  // 當前查看的設備
  total: number                   // 總數量
  loading: boolean                // 載入狀態
}
```

**Actions**:
```typescript
fetchList(filters?: EquipmentFilters)  // 取得設備列表（含篩選）
fetchById(id: number)                  // 取得單一設備
fetchByQR(assetCode: string)           // 透過 Asset Code 取得設備
create(data: any)                      // 新增設備
update(id: number, data: any)          // 更新設備
remove(id: number)                     // 刪除設備（軟刪除）
clearCurrent()                         // 清除當前設備
```

**subEquipmentStore** (`stores/subEquipment.ts`)

**State**:
```typescript
{
  subEquipmentList: SubEquipment[]      // 子設備列表
  currentSubEquipment: SubEquipment | null
  loading: boolean
}
```

**Actions**:
```typescript
fetchList(parentEquipmentId: number)   // 取得特定主設備的子設備列表
fetchById(id: number)                  // 取得單一子設備
create(data: any)                      // 新增子設備
update(id: number, data: any)          // 更新子設備
remove(id: number)                     // 刪除子設備
```

### 5.2 API 層架構

**equipmentApi** (`api/equipment.ts`)

主要方法:
```typescript
list(filters?: EquipmentFilters)       // GET /equipment
get(id: number)                        // GET /equipment/{id}
getByQR(assetCode: string)             // GET /equipment/by-qr/{assetCode}
create(data: EquipmentCreateRequest)   // POST /equipment
update(id: number, data: Partial<...>) // PUT /equipment/{id}
delete(id: number)                     // DELETE /equipment/{id}
getLogs(id: number)                    // GET /equipment/{id}/logs
updateLog(equipmentId, logId, data)    // PUT /equipment/{equipmentId}/logs/{logId}
deploy(id, locationId, notes, lat, lng) // POST /equipment/{id}/deploy
return(id, locationId, notes, lat, lng) // POST /equipment/{id}/return
repair(id, notes)                      // POST /equipment/{id}/repair
sendToCalibration(id, notes)           // POST /equipment/{id}/send-to-calibration
addNote(id, note, lat, lng)            // POST /equipment/{id}/note
getQRCode(id)                          // GET /qrcode/{id}
```

**subEquipmentApi** (`api/subEquipment.ts`)

主要方法:
```typescript
list(parentEquipmentId?: number)       // GET /sub-equipment
get(id: number)                        // GET /sub-equipment/{id}
create(data: SubEquipmentCreateRequest) // POST /sub-equipment
update(id: number, data: Partial<...>) // PUT /sub-equipment/{id}
delete(id: number)                     // DELETE /sub-equipment/{id}
getLogs(id: number)                    // GET /sub-equipment/{id}/logs
getQRCode(id: number)                  // GET /qrcode/sub/{id}
```

### 5.3 資料流動方向

```
[設備列表載入]
Component (EquipmentListView)
  → Store (equipmentStore.fetchList)
    → API (equipmentApi.list)
      → Backend (/api/equipment)
    ← Response { equipments, total }
  ← Update State (equipmentList, total)
← Re-render UI

[設備詳情載入]
Component (EquipmentDetailView)
  → Store (equipmentStore.fetchById)
    → API (equipmentApi.get)
      → Backend (/api/equipment/{id})
    ← Response Equipment
  ← Update State (currentEquipment)
  → 同時載入 QR Code (equipmentApi.getQRCode)
  → 同時載入 Logs (equipmentApi.getLogs)
← Re-render UI

[設備狀態變更]
User Action (e.g., Deploy Button)
  → Component Method (handleDeploy)
    → API Direct Call (equipmentApi.deploy)
      → Backend (/api/equipment/{id}/deploy)
    ← Success
  → Store Refresh (equipmentStore.fetchById)
  → Logs Refresh (loadLogs)
← UI Update

[編輯 Log]
User Action (Edit Button in Log Row)
  → Open Modal (showEditLogModal = true)
  → Fill Form (editLogForm)
  → Submit (handleUpdateLog)
    → API Direct Call (equipmentApi.updateLog)
      → Backend (/api/equipment/{id}/logs/{logId})
    ← Success
  → Update Local Log (logs.value[index] = response.data)
  → Close Modal
← UI Update (顯示 "edited ×N")
```

**缺點**:

## 6. Sub-Equipment 子設備管理

### 6.1 設計理念

**獨立管理模式**:
- 每個子設備有獨立的 Asset Code（格式: `{Parent}-{Seq}`）
- 每個子設備有獨立的 QR Code
- 每個子設備有獨立的 Status
- 每個子設備有獨立的 Activity Log

**與主設備關係**:
- 外鍵關聯: `parent_equipment_id` → `equipments.id`
- CASCADE DELETE: 刪除主設備時，所有子設備也被刪除
- 在主設備詳細頁面中嵌入 SubEquipmentList 組件

### 6.2 Asset Code 自動產生

**規則**:
```
主設備: {CATEGORY}-{YEAR}-{SEQ}
範例: MBES-2025-001

子設備: {Parent Asset Code}-{SubSeq}
範例: MBES-2025-001-01
      MBES-2025-001-02
      MBES-2025-001-03
```

**後端實作**:
```python
async def generate_sub_equipment_asset_code(parent_asset_code: str, db: AsyncSession) -> str:
    # 查詢相同 parent 的子設備數量
    pattern = f"{parent_asset_code}-%"
    result = await db.execute(
        select(func.count(SubEquipment.id))
        .where(SubEquipment.asset_code.like(pattern))
    )
    count = result.scalar()
    next_sequence = count + 1
    return f"{parent_asset_code}-{next_sequence:02d}"  # 02d = 兩位數，補零
```

### 7.2 Log 資料結構

```typescript
interface EquipmentLog {
  id: number
  equipment_id: number

  new_value?: string                  // 新值（不可編輯）

  created_by?: number
  created_by_username?: string
```

### 7.3 編輯規則

**可編輯欄位**:
- `description` (必填)
- `latitude` (選填)
- `longitude` (選填)

**不可編輯欄位**:
- `log_type` - 記錄類型不可變更
- `old_value` - 變更前的值不可變更
- `new_value` - 變更後的值不可變更
- `created_at` - 建立時間不可變更
- `created_by` - 建立者不可變更

**編輯歷史追蹤**:
```
首次編輯:
├─ 儲存 original_description, original_latitude, original_longitude
├─ 更新 description, latitude, longitude
├─ 設定 edited_at = 現在時間
├─ 設定 edited_by = 當前使用者
└─ edit_count = 1

第 N 次編輯:
├─ 不改變 original_* 欄位（保留首次的原始值）
├─ 更新 description, latitude, longitude
├─ 更新 edited_at = 現在時間
├─ 更新 edited_by = 當前使用者
└─ edit_count += 1
```

**權限要求**:
- 編輯 Log: Manager+
- 查看編輯歷史: 所有登入用戶

## 附錄

### A. 設備狀態完整定義

| Status | 中文 | 說明 | 可執行操作 |
|--------|------|------|-----------|
| `ordering` | 訂購中 | 設備已訂購但尚未到貨 | Edit, Deploy (到貨後) |
| `in_stock` | 庫存中 | 設備在庫房中，可供使用 | Deploy, Repair, Calibration |
| `deployed` | 部署中 | 設備正在現場使用 | Return, Repair, Calibration |
| `rented` | 租賃中 | 設備已租出給客戶 | Return |
| `repair` | 維修中 | 設備正在維修 | (維修完成後手動改為 in_stock) |
| `calibrating` | 校正中 | 設備正在進行校正 | (校正完成後手動改為 in_stock) |
| `disposed` | 已報廢 | 設備報廢，不再使用 | (僅 Admin 可刪除) |
| `lost` | 遺失 | 設備遺失 | (僅 Admin 可刪除) |

| 檔案類型 | 允許格式 | 大小限制 |

| Calibration Report | PDF | 10 MB |
